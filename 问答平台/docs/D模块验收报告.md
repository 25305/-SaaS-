# 成员 D 模块验收报告

## 交付范围

- 模块 E：租户总限流与 API Key 限流、滑动窗口、`Retry-After`、租户前缀缓存、TTL、知识库变更失效、缓存命中率。
- 模块 F：物化 `usage_summary`、Key 汇总和延迟桶汇总；后台每五分钟刷新；看板仅读取汇总表；账单明细/CSV/Excel/可追溯性抽样校验。
- 模块 H：登录、租户管理、工作台、Key 管理、问答体验和账单六个功能视图，统一加载/错误/空数据状态以及 ECharts 图表。

## 验收操作

1. 后端目录执行 `py -3.11 -m pytest tests -q`。
2. 前端目录执行 `npm run verify:d`、`npm run build`。
3. 启动后端后，用管理员账号登录前端；分别进入“租户管理”“工作台”“Key 管理”“问答体验”“账单与导出”。
4. 将 `TENANT_RATE_LIMIT_PER_MINUTE=1` 后连续问答两次，第二次应为 429 且响应头带 `Retry-After`。
5. 在问答后修改任一知识库文档，再次问答应为缓存未命中；工作台的缓存命中率会在汇总刷新后显示。
6. 在账单页点击“验证可追溯性”，结果为抽样账单均可按 `request_id` 回查流水。

## 技术决策

- 限流选滑动窗口，避免固定窗口在边界产生双倍突发；缓存 key 固定以 `t:{tenant_id}:` 开头，按租户精确清理并避免串数据。
- 汇总任务以最多五分钟的数据延迟换取看板查询的稳定耗时。`/api/usage/dashboard` 仅读取汇总表，不扫描不可变流水。
- 缓存命中流水 Token 为零，但仍记请求数；因此命中率既是性能指标，也是可估算的模型 Token 节省指标。
