# 部署说明

## 一键启动（Windows）

仓库根目录双击 `start.cmd`：自动检查环境 → 按需安装依赖 → 启动后端(8000) 与前端(5173) → 打开浏览器。
关闭弹出的「后端」与「前端」两个窗口即停止服务。

## 开发环境

Python 需 3.10+（当前机器实测 3.13 可用），Node.js 需 18+。进入 `问答平台/backend` 后执行：

```powershell
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

> 用 `py` 启动器时把 `python` 换成 `py -3`（按本机已安装版本，如 `py -3.13`）。

前端在仓库根目录的 `frontend`：

```powershell
npm install
npm run dev
```

## MySQL 8.0

复制 `问答平台/backend/.env.example` 为 `问答平台/backend/.env`，把 `DATABASE_URL` 改成实际账号：

```
DATABASE_URL=mysql+pymysql://smartqa:Smartqa%40123@127.0.0.1:3306/smartqa_saas?charset=utf8mb4
```

> 密码含 `@` `:` `/` 等字符时须 URL 转义（`@` → `%40`），否则会被解析成主机分隔符。

建库与专用账号（以 root 执行一次）：

```sql
CREATE DATABASE IF NOT EXISTS smartqa_saas CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER IF NOT EXISTS 'smartqa'@'127.0.0.1' IDENTIFIED BY '<强密码>';
GRANT ALL PRIVILEGES ON smartqa_saas.* TO 'smartqa'@'127.0.0.1';
FLUSH PRIVILEGES;
```

启动服务时会自动创建缺失表并写入演示租户；生产环境必须更换 `JWT_SECRET`、关闭演示账号，
并先完成备份恢复演练。

**本机状态（2026-10-18）**：`smartqa_saas` 已创建，`.env` 已指向 MySQL，建表/种子/登录/问答/看板/账单
均已实测通过；MySQL 备份恢复演练与 `FOR UPDATE` 并发演练尚未做，详见 [运维手册](运维手册.md)。

## 验证

后端（工作目录 `问答平台/backend`）：

```powershell
python -m pytest tests -q      # 期望 71 passed
```

前端（工作目录 `frontend`）：

```powershell
npm run build
```

没有配置真实模型时，`/health` 会以 503 标记模型未配置；这不影响 `/docs`、
租户隔离、配额、限流和账单接口的本地演示。

## 目录约定

唯一后端为 `问答平台/backend/`，唯一文档集为 `问答平台/docs/`，前端为仓库根目录的 `frontend/`。
仓库根目录下曾存在 `backend/` 与 `docs/` 两份历史遗留的部分副本，已移除；若需取回可执行
`git checkout HEAD -- backend docs`。
